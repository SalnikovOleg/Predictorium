# Plan: Slug in React Router, ID in API — React-only

## Problem

React Router URL uses slug (`/tournaments/:slug/`), but API requests should use numeric ID (`GET /tournaments/{id}`). Backend supports both.

## Current State

```
TournamentPage:  useParams → slug → useTournament(slug) → GET /tournaments/{slug}
EventPage:       useParams → slug → useEvent(slug)      → GET /events/{slug}
```

## Solution: Dependent Queries with React Query

Use **two sequential queries**: first resolve slug→id via a lightweight endpoint, then fetch data by id.

### Flow

```
URL slug  →  resolve query (GET /tournaments/resolve/:slug → { id })  →  main query (GET /tournaments/{id})
```

### Changes

#### 1. Add resolve API functions

**`src/features/tournament/api/tournament.ts`** — add:
```ts
export async function resolveTournamentSlug(slug: string): Promise<number> {
  const { data } = await apiClient.get<{ data: { id: number } }>(`/tournaments/resolve/${slug}`)
  return data.data.id
}
```

**`src/features/event/api/event.ts`** — add:
```ts
export async function resolveEventSlug(slug: string): Promise<number> {
  const { data } = await apiClient.get<{ data: { id: number } }>(`/events/resolve/${slug}`)
  return data.data.id
}
```

#### 2. Update hooks to use dependent queries

**`src/features/tournament/hooks/useTournament.ts`**:
```ts
export function useTournament(slug: string) {
  const resolveQuery = useQuery({
    queryKey: ['tournament-resolve', slug],
    queryFn: () => resolveTournamentSlug(slug),
  })

  return useQuery({
    queryKey: ['tournament', resolveQuery.data],
    queryFn: () => fetchTournament(resolveQuery.data!),
    enabled: !!resolveQuery.data,
  })
}
```

**`src/features/event/hooks/useEvent.ts`**:
```ts
export function useEvent(slug: string) {
  const resolveQuery = useQuery({
    queryKey: ['event-resolve', slug],
    queryFn: () => resolveEventSlug(slug),
  })

  return useQuery({
    queryKey: ['event', resolveQuery.data],
    queryFn: () => fetchEvent(resolveQuery.data!),
    enabled: !!resolveQuery.data,
  })
}
```

#### 3. Revert API functions to use id

**`src/features/tournament/api/tournament.ts`** — revert:
```ts
export async function fetchTournament(id: number): Promise<TournamentResponse> {
  const { data } = await apiClient.get<TournamentResponse>(`/tournaments/${id}`)
  return data
}
```

**`src/features/event/api/event.ts`** — revert:
```ts
export async function fetchEvent(id: number): Promise<Event> {
  const { data } = await apiClient.get<{ data: Event }>(`/events/${id}`)
  return data.data
}
```

#### 4. Backend: add resolve routes (if not already present)

```
GET /api/tournaments/resolve/{slug}  → { id }
GET /api/events/resolve/{slug}       → { id }
```

## Tradeoff

- **+2 network requests** per page load (resolve + fetch). But the resolve endpoint is tiny (returns one int), so latency is minimal.
- **Alternative (simpler)**: Just use slug in the API too (current implementation). One request, backend resolves internally. The slug column should have a unique index, so performance is equivalent to PK lookup.
