# Plan: Client-Side Stake Request Rate Limiting

## Problem

Every click on an outcome button immediately fires `POST /stake`. Rapid clicks (e.g., switching between outcomes) flood the backend with requests.

## Solution: Debounced Stake Submission

Debounce the API call so only the **last** selection after the user stops clicking is sent. Combine with optimistic UI for instant feedback.

### Approach

1. **Debounce the mutation** — collect stake params, wait 500ms after last click, then send one request with the final selection
2. **Optimistic UI** — local state updates immediately (already done), so the user sees instant feedback
3. **Show loading state** — disable buttons / show spinner while request is in flight

## Files to Modify

### 1. `src/features/event/hooks/useEvent.ts`

Wrap `useCreateStake` with debounce logic using `useRef` + `setTimeout`:

```ts
import { useRef, useCallback } from 'react'
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { createStake } from '../api/event'

export function useCreateStake() {
  const queryClient = useQueryClient()
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null)

  const mutation = useMutation({
    mutationFn: createStake,
    onSuccess: (_data, variables) => {
      queryClient.invalidateQueries({ queryKey: ['event', variables.event_id] })
    },
  })

  const mutateDebounced = useCallback(
    (payload: Parameters<typeof createStake>[0]) => {
      if (timerRef.current) clearTimeout(timerRef.current)
      timerRef.current = setTimeout(() => {
        mutation.mutate(payload)
      }, 500)
    },
    [mutation],
  )

  return {
    ...mutation,
    mutate: mutateDebounced,
  }
}
```

### 2. `src/pages/Event/EventPage.tsx`

No changes needed — `handleSelectOutcome` already calls `createStake.mutate()` which will now be debounced.

## Behavior

- User clicks outcome A → local state updates instantly → 500ms timer starts
- User clicks outcome B within 500ms → local state updates → timer resets → 500ms timer starts
- User stops clicking → after 500ms, ONE request fires with the final selection
- If user deselects (clicks same outcome) within 500ms → timer fires but `newSelected` is null → no request sent

## Verification

1. Open EventPage, open browser Network tab
2. Click outcomes rapidly → only ONE request fires after 500ms pause
3. UI updates instantly on each click (optimistic)
4. Deselecting an outcome cancels the request
