# Fix ResultResource: Participant Selectors Not Showing Event Participants

## Problem

When creating a Result via the modal on `ListResults`, the participant dropdowns show no options.

## Root Cause

The `Hidden::make('event_id')` field uses:
```php
->default(fn () => request()->query('tableFilters')['event_id'] ?? null)
```

This reads from the HTTP query string. But when the `CreateAction` modal opens via Livewire AJAX, the `request()->query()` context may not contain `tableFilters[event_id]`, causing the Hidden field to default to `null`.

Meanwhile, the participant Select closures use `$get('event_id')` which resolves from the form state. If the Hidden field is null, the closures return `[]`.

**The `MarketResource` (which works) uses a different pattern:**
```php
// Hidden field
->default(fn () => request()->query('event_id'))

// Select closures  
$eventId = $get('event_id') ?? request()->query('event_id');
```

It has a **dual fallback**: `$get('event_id')` from form state, OR `request()->query('event_id')` from the URL. The `ResultResource` lacks this fallback.

Additionally, the Repeater uses `$get('../../event_id')` which I verified resolves correctly to root-level `event_id` via `resolveRelativeStatePath()` — but if the root value is null, it still returns null.

## Fix

**File**: `app/Filament/Resources/ResultResource.php`

### 1. Add fallback to Hidden field default (line 43)

```php
// Before
Forms\Components\Hidden::make('event_id')
    ->default(fn () => request()->query('tableFilters')['event_id'] ?? null)
    ->reactive(),

// After — multiple fallback sources
Forms\Components\Hidden::make('event_id')
    ->default(fn () => request()->query('tableFilters')['event_id'] ?? request()->query('event_id') ?? null),
```

Also remove `->reactive()` — a hidden field doesn't need to trigger re-renders.

### 2. Add fallback to single participant Select (line 71)

```php
// Before
$eventId = $get('event_id');

// After
$eventId = $get('event_id') ?? request()->query('tableFilters')['event_id'] ?? request()->query('event_id');
```

### 3. Add fallback to Repeater participant Select (line 107)

```php
// Before
$eventId = $get('../../event_id');

// After — use root-level $get with fallback
$eventId = $get('event_id') ?? request()->query('tableFilters')['event_id'] ?? request()->query('event_id');
```

In Filament, `$get('event_id')` from inside a Repeater resolves from root if the key doesn't exist at the current nesting level (verified via `resolveRelativeStatePath()`).

## Verification

1. Open Filament admin → Trading → Events → click Results on an event → click Create
2. Select a ResultType → verify participant dropdown shows participants from that event
3. Test with `value_type='positions'` → verify Repeater participant dropdowns work
4. Test editing an existing Result → verify participants still show
